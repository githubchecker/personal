## 🗺️ $\color{#0D47A1}\blacksquare\space\color{#1565C0}{\textsf{Stage 0 — Concept Map}}$

**The problem:** Python lets you write three fundamentally different kinds of methods inside a class. Pick the wrong one and you break subclass inheritance, skip validation, or end up needing an instance just to call a pure utility function.

**Where it fits:**
- Builds on: 12.1 (`self`, `__init__`), 12.2 (inheritance and `super()`)
- Unlocks: ABCs (12.6 — `@classmethod` alternative constructors are everywhere in AI libs)

## 🔑 $\color{#4A148C}\blacksquare\space\color{#6A1B9A}{\textsf{New Terms (Plain English)}}$

| Term | One-line meaning |
| :--- | :--- |
| **Instance method** | A regular method — receives `self` (the current object), can read/write instance state |
| **`@classmethod`** | A method that receives `cls` (the class itself) — used for alternative constructors and class-level logic |
| **`@staticmethod`** | A plain function namespaced inside a class — receives neither `self` nor `cls` |
| **`cls`** | Conventional name for the class parameter in `@classmethod`, just like `self` for instances |
| **Alternative constructor** | A `@classmethod` that parses a different input format and returns a new instance via `cls(...)` |
| **Constructor overloading** | Python can't define two `__init__` with different signatures — `@classmethod` is the Python-native solution |

## 🎈 $\color{#00695C}\blacksquare\space\color{#00897B}{\textsf{Stage 1 — The Simple Idea }}$

Think of a restaurant kitchen:
- **Instance method** = a cook working on *their* specific dish — they have access to their own station's ingredients (`self`).
- **`@classmethod`** = the head chef who knows the whole kitchen setup (`cls`) and can spin up a new station from a recipe card.
- **`@staticmethod`** = a utility tool (blender, timer) — doesn't care which cook or which kitchen, just does its job.

> **The "Aha!"**: Use `@classmethod` when the action needs to know about the class (creating instances, reading class-level config). Use `@staticmethod` when the action is genuinely independent — just a helper function that lives inside the class for organization.

### $\color{#D84315}\blacktriangleright\space\color{#BF360C}{\textsf{12.8 Method Types: Instance, @classmethod, and @staticmethod}}$

#### 1. Constructor Overloading — The Python Way

Python **cannot** define multiple `__init__` methods. The second one silently overwrites the first:

```python
# 🚫 BROKEN: Second __init__ silently overwrites the first
class Bad:
    def __init__(self, text):
        self.text = text
    def __init__(self, text, author):   # ← kills the one above
        self.text = text
        self.author = author

Bad("Hello")  # 💥 TypeError: __init__() missing 1 required argument: 'author'
```

**Fix A — Default arguments (when parameters are optional):**

```python
# 🔵 Solution A: Default args handle optional parameters in ONE __init__
class Document:
    def __init__(self, text, metadata=None, author="Unknown"):
        self.text = text
        self.metadata = metadata if metadata is not None else {}
        self.author = author

doc1 = Document("Hello world")                       # 1 arg
doc2 = Document("Summary text", author="Alice")      # 2 args
doc3 = Document("AI Notes", {"tokens": 120}, "Bob") # 3 args
```

**Fix B — `@classmethod` alternative constructors (when input format differs):**

```python
# 🟢 Solution B: @classmethod factory for different data representations
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    # Alternative constructor: builds a User from "Name, Age" string
    @classmethod
    def from_string(cls, text):
        name, age = text.split(",")
        return cls(name.strip(), int(age.strip()))  # ← cls() not User()!

    # Alternative constructor: builds a User from a dictionary
    @classmethod
    def from_dict(cls, data):
        return cls(data["name"], data["age"])

# Primary constructor:
u1 = User("Rex", 5)

# Alternative constructors (clean and readable!):
u2 = User.from_string("Alice, 30")
u3 = User.from_dict({"name": "Bob", "age": 25})

print(u2.name, u2.age)   # 'Alice' 30
print(u3.name, u3.age)   # 'Bob' 25
```

> **Why `cls(...)` instead of `User(...)`?**  
> Using `cls` ensures that if a subclass `AdminUser(User)` inherits `from_string`, calling `AdminUser.from_string("Alice, 30")` correctly returns an `AdminUser` instance, not a base `User`.

#### 2. Method Types Compared — Decision Table

| Feature | Instance Method | `@classmethod` | `@staticmethod` |
| :--- | :--- | :--- | :--- |
| **First Argument** | `self` (current instance) | `cls` (the class itself) | *None* — plain args only |
| **Access instance state (`self.x`)?** | ✅ Yes | 🚫 No | 🚫 No |
| **Access class state (`cls.x`)?** | ✅ via `self.__class__.x` | ✅ directly via `cls.x` | ⚠️ Only by hardcoding `ClassName.x` |
| **Subclass polymorphism?** | ✅ Yes | ✅ Yes (`cls` → child class) | 🚫 No — hardcoded name won't adapt |
| **Call without an instance?** | 🚫 No — needs `obj.method()` | ✅ Yes — `ClassName.method()` | ✅ Yes — `ClassName.method()` |
| **Primary use case** | Read/write per-instance data | Alternative constructors, class-level config | Isolated utility namespaced in class |

**In code — all three call sites proved in one block:**

```python
class TextProcessor:
    default_encoding = "utf-8"   # class-level variable (shared config)

    def __init__(self, encoding=None):
        self.encoding = encoding or self.default_encoding   # instance attribute

    # 🔵 INSTANCE METHOD — operates on this specific object's state
    def process(self, text):
        cleaned = self.clean_whitespace(text)   # can call static utility
        return cleaned.encode(self.encoding)     # uses self.encoding

    # 🟢 CLASS METHOD — receives `cls`, perfect for alternative constructors
    @classmethod
    def from_ascii(cls):
        """Alternative constructor: TextProcessor pre-configured for ASCII."""
        instance = cls(encoding="ascii")         # cls() → subclasses inherit correctly
        return instance

    @classmethod
    def set_default_encoding(cls, new_encoding):
        """Modifies class-level state dynamically."""
        cls.default_encoding = new_encoding

    # 🟣 STATIC METHOD — pure function, no self or cls needed
    @staticmethod
    def clean_whitespace(text):
        return " ".join(text.strip().split())


# --- Execution & Verification ---

# 🟣 @staticmethod: callable on class OR instance, no state needed
clean = TextProcessor.clean_whitespace("  hello    world \n ")
print(clean)                             # 'hello world'   ← @staticmethod

# 🟢 @classmethod: alternative constructor without creating base instance first
ascii_proc = TextProcessor.from_ascii()
print(ascii_proc.encoding)               # 'ascii'         ← @classmethod

# 🔵 Instance Method: requires an initialized object
proc = TextProcessor()
print(proc.process(" AI engineering "))  # b'AI engineering' ← instance method
```

#### 3. Technical Nuances

**Can a `@staticmethod` use class variables?**

| | `@classmethod` | `@staticmethod` |
| :--- | :--- | :--- |
| Read class var | `cls.default_encoding` | Must hardcode: `TextProcessor.default_encoding` |
| Works in subclass? | ✅ — `cls` auto-resolves to child | 🚫 — hardcoded name always points to base class |

```python
# ⚙️ Polymorphism difference: cls vs. hardcoded class name
class Base:
    encoding = "utf-8"

    @classmethod
    def get_enc_cls(cls):
        return cls.encoding          # ← 'cls' resolves to whatever calls this

    @staticmethod
    def get_enc_static():
        return Base.encoding         # ← always Base, never the child!

class Child(Base):
    encoding = "utf-16"

print(Child.get_enc_cls())           # 'utf-16'  ✅ cls resolved to Child
print(Child.get_enc_static())        # 'utf-8'   🚫 hardcoded Base, ignores Child.encoding
```

> [!TIP]
> **⚙️ Under the Hood — Memory & GC Impact:**
> - `@staticmethod`: calling `ClassName.static_method` returns the **raw function object** directly — no bound method wrapper created. Slightly more lightweight than instance methods.
> - `@classmethod`: returns a **bound method** wrapping the function + the class object. Lightweight; holds no reference to instances.
> - Neither `@staticmethod` nor `@classmethod` holds a reference to instance objects (`self`) — they **never prevent instance garbage collection** and cannot cause circular-reference leaks.
> - Both are created and bound **at module import time** (when Python parses the class) — they exist in memory regardless of whether zero or ten thousand instances are created.

> [!NOTE]
> **Architect's Rule: `@staticmethod` vs. Module-Level Function?**  
> If a helper doesn't touch `self` or `cls`, you have two choices:  
> - `@staticmethod` inside the class → when the utility is conceptually tied to the class domain and callers expect `TextProcessor.clean_whitespace(...)`.  
> - Module-level `def clean_whitespace(text):` → when the utility is generic and used by multiple unrelated classes.  
> **Rule of thumb:** Is it *about* the class? → `@staticmethod`. Is it *shared* across classes? → module-level function.

## 🚀 $\color{#0D47A1}\blacksquare\space\color{#1565C0}{\textsf{Stage 3 — In Practice / Why It Matters}}$

- **`@classmethod` alternative constructors** are the standard pattern in every major AI library:
  - `SentenceTransformer.from_pretrained("model-name")` — classmethod factory
  - `AutoTokenizer.from_pretrained(...)` — classmethod factory
  - `pd.DataFrame.from_dict(...)` — classmethod factory
- **`@staticmethod`** appears as validation helpers, token counters, text normalizers — functions that belong to the class conceptually but don't need any state.
- **Instance methods** are the default for everything that reads or mutates per-object data.

## 🐛 $\color{#880E4F}\blacksquare\space\color{#AD1457}{\textsf{Common Errors and Fixes}}$

| What you see | Cause | Fix |
| :--- | :--- | :--- |
| Second `def __init__` silently ignored | Python can only have one `__init__` — second overwrites first | Use default args or `@classmethod` alternative constructors |
| `TypeError: method() missing 1 required argument: 'self'` | Called `Class.instance_method()` without an instance | Create an instance first: `obj = Class(); obj.method()` |
| Child subclass gets wrong type from `@classmethod` | Used `User(...)` instead of `cls(...)` inside classmethod | Always use `cls(...)` to preserve subclass identity |
| `@staticmethod` doesn't see child's class variable | Hardcoded class name in static method | Switch to `@classmethod` to get polymorphic `cls.var` access |

## 📌 $\color{#1B5E20}\blacksquare\space\color{#2E7D32}{\textsf{Quick Reference}}$

```python
class TextProcessor:
    default_encoding = "utf-8"    # class attribute

    def __init__(self, encoding=None):
        self.encoding = encoding or self.default_encoding  # instance attribute

    # INSTANCE METHOD — needs an object
    def process(self, text):
        return text.encode(self.encoding)

    # @classmethod — alternative constructor / class-level operations
    @classmethod
    def from_ascii(cls):
        return cls(encoding="ascii")    # ← cls() not TextProcessor()!

    @classmethod
    def set_default(cls, enc):
        cls.default_encoding = enc

    # @staticmethod — pure utility, no state
    @staticmethod
    def clean(text):
        return " ".join(text.strip().split())


# Call sites:
TextProcessor.clean("  hi  ")           # @staticmethod — no instance needed
TextProcessor.from_ascii()              # @classmethod  — no instance needed
proc = TextProcessor()
proc.process("AI")                      # instance method — needs an object
```

## 🛑 $\color{#B71C1C}\blacksquare\space\color{#D32F2F}{\textsf{STOP — Self-Check}}$

A subclass `FrenchProcessor(TextProcessor)` overrides `default_encoding = "latin-1"`. You call `FrenchProcessor.from_ascii()`. **Does the returned object have `encoding = "ascii"` or `"latin-1"`, and what type is it?**

<details>
<summary><b>🔍 Click to Reveal the Answer</b></summary>

<br/>

The object has `encoding = "ascii"` and its type is `FrenchProcessor` (not `TextProcessor`).

- `FrenchProcessor.from_ascii()` calls `cls(encoding="ascii")` where `cls` is `FrenchProcessor`.
- `cls(encoding="ascii")` calls `FrenchProcessor.__init__(self, encoding="ascii")`.
- Inside `__init__`, `self.encoding = encoding or self.default_encoding` → since `"ascii"` is truthy, `self.encoding = "ascii"`.
- The returned instance is a `FrenchProcessor` object because `cls` resolved to `FrenchProcessor` — this is why `cls(...)` rather than `TextProcessor(...)` is the correct pattern.

**If `@staticmethod` had been used instead:** it would have called `TextProcessor(encoding="ascii")` directly (hardcoded), returning a `TextProcessor` object — breaking the subclass.
